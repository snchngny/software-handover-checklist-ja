開発会社向け 顧客案件の
引継ぎチェックリスト

社員退職や外注離脱の前に、顧客案件の受入条件、運用、障害対応、取消手順を経営判断者と後任が確認する17項目です。

Markdown版を無料で使う このページで確認する

使い方

  1. 顧客案件ごとにチェックリストを複製
  2. 離脱期限と後任責任者を決めて一緒に確認
  3. 分からない項目は埋めずに「未確認」と記録
  4. 秘密値は書かず、正規の保管場所と取得手順だけを記録

確認日、顧客案件、離脱区分（社員退職・外注離脱）、期限、経営判断者、後任責任者を最初に記録してください。

17項目のチェックリスト

目的と範囲

  • 顧客が何のために使う案件か説明できる
  • 顧客との契約範囲と対象外を区別している
  • repository、顧客向け文書、運用データの正本とアクセス責任者が分かる

受入条件と根拠

  • 完了条件を観察可能な結果で書いている
  • 各条件の確認方法、確認日、結果を残している
  • 未確認事項を成功扱いしていない

日常運用

  • 起動、停止、更新、定期処理の手順がある
  • 入力、出力、保存先、実行者が分かる
  • APIキーやパスワードの実値を書かず、正規の取得方法を示している
  • ログと監視結果の確認場所が分かる

困った時

  • よくある失敗と確認順がある
  • 変更を取り消す条件と手順がある
  • 復旧できない時の連絡先と判断者が分かる
  • 本番へ影響する操作と影響しない確認を区別している

引継ぎ完了

  • 引継ぎ先が手順を見て主要操作を再現した
  • 不足、例外、期限付き対応を一覧にした
  • 離脱後の文書更新責任者と次回確認日を決めた

顧客案件の引継ぎを実作業に移す場合

小規模開発会社の顧客案件に使える、受入条件、確認根拠、利用・障害対応、rollbackの日本語Markdownテンプレート5点と架空の記入例です。社員退職・外注離脱前の準備に利用できます。
